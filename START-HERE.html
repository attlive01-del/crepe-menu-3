دليل تشغيل مشروع Crepe Menu المعدّل

الحزمة تضم ملفات المشروع الكاملة، وإعداد Supabase، والاختبارات، وتعليمات بناء التطبيق. فك ضغط crepe-menu-complete.zip للحصول على مجلد crepe-menu.

هذه ملفات المصدر القابلة للبناء. نسخة Android بصيغة APK تُنشأ لاحقًا من GitHub Actions. يمكنك استخدام الموقع من متصفح الآيفون بعد نشره. لم تُعدّل قاعدة Supabase الحية أو تُنشر هذه النسخة أثناء تجهيز الملفات.

1. جهّز نسخة احتياطية

استخدم مشروع Supabase الحالي المرتبط بقائمتك. احتفظ بنسخة احتياطية من قاعدة البيانات قبل تطبيق SQL؛ إن كانت لديك تعديلات خاصة على الجداول فراجعها أولًا أو جرّب التحديث في مشروع تجريبي.

ملف SQL يحافظ على صفوف القائمة، ويضيف صلاحيات الإدارة وإصدارات البيانات. يزيل عمود admin_pin القديم وسياسات الوصول القديمة للجداول المحددة. بعد تطبيقه ستحتاج النسخة الجديدة وحساب المدير للتعديل؛ الواجهة القديمة غير المسجّلة لن تستطيع الحفظ.

إذا كانت على جهازك تغييرات قديمة لم تُرفع إلى Supabase، احتفظ ببيانات المتصفح قبل مسحها؛ النسخة الجديدة لا ترسل الطابور القديم تلقائيًا. التفاصيل في README داخل المشروع.

2. طبّق إعداد Supabase

  1. افتح لوحة Supabase واختر المشروع الصحيح.
  2. افتح SQL Editor ثم أنشئ استعلامًا جديدًا.
  3. الصق محتوى الملف supabase/migrations/202609130001_secure_menu.sql كاملًا، ثم اضغط Run. يمكنك أيضًا نسخه من المربع أدناه؛ هو نفس الملف المرفق باسم crepe-menu-supabase.sql.
  4. انتظر نتيجة النجاح قبل الانتقال إلى إنشاء المدير. إذا ظهر خطأ، احتفظ برسالته ولا تنفّذ الأوامر على أجزاء عشوائية.

السكربت يجهز الجداول وسياسات RLS وقائمة المديرين وتحديثات Realtime وحاوية الصور crepe-menu-images. يمكن تكراره على البنية المتوافقة. إذا سبق أن أنشأت سياسات Storage عامة أخرى، راجعها لأنها لا تُحذف بهذا السكربت.

3. أنشئ حساب المدير

  1. في مشروع Supabase نفسه، افتح Authentication → Users.
  2. أنشئ مستخدمًا ببريد إلكتروني تملكه وكلمة مرور تختارها. أكّد البريد، أو استخدم خيار تأكيد المستخدم أثناء إنشائه إذا كان ظاهرًا.
  3. ارجع إلى SQL Editor ونفّذ النص التالي بعد استبدال YOUR_ADMIN_EMAIL بنفس البريد الذي أنشأت به المستخدم:
insert into public.menu_admins (user_id)
select id from auth.users
where email = 'YOUR_ADMIN_EMAIL'
on conflict (user_id) do nothing
returning user_id;

إن أعاد الاستعلام معرّفًا، تمت إضافة صلاحية الإدارة. إن لم يُرجع صفًا، فقد يكون الحساب مديرًا مسبقًا أو البريد غير موجود. يمكنك التحقق باستبدال البريد هنا أيضًا:

select u.id, u.email
from auth.users u
join public.menu_admins a on a.user_id = u.id
where u.email = 'YOUR_ADMIN_EMAIL';

يجب أن يظهر صف الحساب. كلمة المرور لا تُكتب في SQL أو في ملفات المشروع. العضوية في menu_admins هي التي تمنح صلاحية الإدارة.

4. انسخ بيانات الاتصال

من زر Connect داخل مشروع Supabase انسخ Project URL وPublishable key. ويمكن العثور على المفتاح من Settings → API Keys. استخدم بيانات نفس المشروع الذي نفّذت فيه SQL.

اسم متغير البيئة في تطبيقكالقيمة
VITE_SUPABASE_URLعنوان مشروع Supabase، مثل https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEYالمفتاح العام الذي يبدأ بـ sb_publishable_. هذا الاسم ثابت في الكود ويقبل أيضًا مفتاح anon القديم.
VITE_PUBLIC_MENU_URLعنوان موقعك المنشور بصيغة HTTPS، مثل https://YOUR_MENU.vercel.app/، دون #/admin.

المفتاح العام متوقع ظهوره في تطبيق المتصفح؛ الحماية تعتمد على RLS وتسجيل الدخول. لا تستخدم service_role أو sb_secret_ في هذه المتغيرات. مرجع مفاتيح Supabase.

5. ارفع ملفات المشروع إلى GitHub

هذه الخطوة أسهل من كمبيوتر حتى تتمكن من رفع المجلدات مع الاحتفاظ بمساراتها.

  1. فك ضغط الحزمة. افتح مجلد crepe-menu الذي يحتوي package.json وsrc.
  2. افتح مستودع attlive01-del/crepe-menu ثم Add file → Upload files.
  3. ارفع محتويات مجلد المشروع في جذر المستودع مع استبدال الملفات المطابقة والحفاظ على المجلدات. يجب أن يبقى package.json في الجذر، دون وضع المشروع داخل مجلد إضافي. رفع ZIP وحده لا يحدّث التطبيق.
  4. تأكد من وجود package-lock.json ومن وصول ملفات .github/workflows؛ قد يخفي جهازك أسماء الملفات التي تبدأ بنقطة. إذا كان bun.lock القديم ما زال في المستودع، احذفه لأن هذه النسخة تعتمد npm.
  5. اكتب رسالة مثل Fix menu authentication and saving واحفظ التغييرات على main كما طلبت. راجع أي تعديلات أحدث أجريتها أنت قبل استبدال ملفاتها.

إذا كان Vercel ينشر تلقائيًا من main، اضبط متغيرات البيئة الموضحة في الخطوة التالية قبل حفظ تغييرات GitHub. دليل رفع الملفات إلى GitHub.

6. شغّل الموقع على Vercel

إذا كنت تستخدم Vercel، افتح المشروع المرتبط بمستودعك، ثم Settings → Environment Variables. أضف المتغيرات الثلاثة في الجدول السابق، وحدد بيئة Production، وأضفها إلى Preview أيضًا إذا كنت ستختبر نسخة معاينة. اضغط حفظ.

إعدادات البناء لهذه النسخة: Framework: Vite، وInstall Command: npm ci، وBuild Command: npm run build، وOutput Directory: dist، مع Node.js 22 أو أحدث. إذا كان مشروعك مضبوطًا على Bun، عدّل أمر التثبيت إلى npm.

بعد رفع الملفات أنشئ نشرًا جديدًا أو استخدم Redeploy، لأن تغيير متغيرات البيئة لا يغيّر النسخة التي بُنيت سابقًا. استخدم رابط الإنتاج الثابت الذي يفتحه الزبائن؛ ضعه في VITE_PUBLIC_MENU_URL قبل توليد وطباعة QR. دليل متغيرات Vercel.

للتشغيل المحلي على كمبيوتر، انسخ .env.example إلى .env.local واضبط القيم، ثم شغّل:

npm ci
npm run check
npm run dev

7. ادخل لوحة الإدارة وتحقق من التشغيل

افتح رابط الموقع العادي لرؤية قائمة الزبائن. للدخول كمدير أضف #/admin إلى نهاية الرابط، مثل https://YOUR_MENU.vercel.app/#/admin، ثم أدخل بريد المستخدم وكلمة مروره.

  1. جرّب تعديل سعر واحد، ثم حدّث الصفحة وتأكد أن السعر محفوظ.
  2. جرّب رفع صورة منتج صغيرة. تأكد أنها تظهر بعد الحفظ.
  3. افتح رابط الزبائن في نافذة خاصة أو هاتف آخر. يجب أن تظهر القائمة دون أدوات الإدارة؛ فتح #/admin دون جلسة مدير يعرض تسجيل الدخول.
  4. جرّب QR على جهاز آخر قبل طباعته؛ يجب أن يفتح الموقع المنشور وليس localhost.

الحفظ يحتاج اتصالًا بالخادم. صور حاوية crepe-menu-images عامة للزبائن، والحد بعد الضغط 2 ميغابايت. تغيير العملة الأساسية مع وجود أصناف متوقف حتى لا تتغيّر دلالة الأسعار دون تحويلها؛ يمكن تعديل سعر الصرف.

8. إنشاء APK لأندرويد عند الحاجة

  1. في مستودع GitHub افتح Settings → Secrets and variables → Actions.
  2. في تبويب Secrets أضف عبر New repository secret كلًا من VITE_SUPABASE_URL وVITE_SUPABASE_ANON_KEY بالقيم نفسها.
  3. في تبويب Variables أضف VITE_PUBLIC_MENU_URL برابط موقعك المنشور.
  4. افتح Actions → Build Android APK → Run workflow واختر main.
  5. بعد اكتمال المهمة بنجاح، افتح النتيجة ونزّل الحزمة CrepeCart-Menu-App-Debug من Artifacts. فك ضغطها للحصول على app-debug.apk.

هذا APK تجريبي لأندرويد، ولا يُثبّت على الآيفون. إصدار متجر Google Play يحتاج إعداد توقيع ونسخة Release مستقلًا. إن فشل التشغيل التلقائي قبل إضافة المتغيرات، شغّل المهمة مرة أخرى بعد ضبطها. دليل أسرار GitHub Actions.
