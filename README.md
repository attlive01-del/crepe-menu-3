# Crepe Menu — قائمة الكريب

تطبيق React وTypeScript وSupabase لعرض القائمة وتعديلها، مع مشروع Android يُولّد بواسطة Capacitor.

## تشغيل النسخة الجديدة

1. استخدم Node.js 22 أو أحدث وشغّل `npm ci`.
2. انسخ `.env.example` إلى `.env.local` واضبط `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` من مشروعك. استخدم مفتاح **anon أو publishable** العام فقط، ولا تستخدم service_role أو secret. إعدادات الربط أصبحت من بيئة البناء؛ إعدادات الرابط والمتصفح القديمة لا تُستخدم.
3. اتبع إعداد قاعدة البيانات وحساب المدير أدناه قبل نشر الواجهة الجديدة.
4. شغّل `npm run dev`. للنسخة النهائية: `npm run build`.
5. الصفحة الافتراضية للزبائن. افتح `#/admin` بعد عنوان الموقع لتسجيل دخول المدير.
6. اضبط `VITE_PUBLIC_MENU_URL` على عنوان HTTPS المنشور لتوليد QR من تطبيق Android أو localhost. على الموقع المنشور يُستخدم عنوان الصفحة إن لم يُضبط المتغير. لا يُولّد التطبيق رابط QR وهميًا أو محليًا.

كل متغير يبدأ بـ VITE يظهر داخل التطبيق المبني. صلاحيات قاعدة البيانات هي الحماية الفعلية؛ إخفاء لوحة الإدارة أو المفتاح العام لا يحمي الجداول.

## إعداد قاعدة البيانات وحساب المدير — خطوة لازمة

تعديل ملفات GitHub **لا يطبّق الحماية على قاعدة Supabase الحية**. لم تُختبر قاعدة الإنتاج أو تُعدّل أثناء هذه الإصلاحات.

1. خذ نسخة احتياطية من جداول المشروع واختبر التحديث على مشروع تجريبي إن أمكن.
2. افتح SQL Editor في Supabase ونفّذ الملف [202609130001_secure_menu.sql](supabase/migrations/202609130001_secure_menu.sql) كاملًا بصلاحيات مالك المشروع. السكربت داخل معاملة ويمكن تكراره؛ يحافظ على بيانات القائمة، ويزيل عمود PIN القديم وسياسات الجداول العامة التي كانت تسمح بالكتابة، ويضيف صلاحيات المدير وإصدارات الصفوف.
3. أنشئ مستخدم المدير في **Authentication → Users** مع بريد وكلمة مرور، ثم نفّذ:

```sql
insert into public.menu_admins (user_id)
select id from auth.users where email = 'REPLACE_WITH_ADMIN_EMAIL'
on conflict (user_id) do nothing
returning user_id;
```

استبدل البريد ببريد الحساب الفعلي. إذا لم يُرجع الاستعلام صفًا، تحقق أن الحساب موجود وأن عضويته لم تكن مضافة من قبل. التسجيل كمستخدم عادي وحده لا يمنح صلاحيات مدير.

4. تحقّق في المشروع التجريبي من أن الزائر والحساب العادي يستطيعان قراءة القائمة ولا يستطيعان تعديلها، وأن حساب المدير يستطيع الحفظ والحذف.
5. اضبط متغيرات البيئة في الاستضافة قبل إعادة البناء والنشر. بعد تطبيق SQL لن تتمكن الواجهة القديمة غير الموثّقة من التعديل؛ استخدم الواجهة الجديدة وحساب المدير.

السكربت يفترض أسماء وبنية الجداول الموجودة في هذا المستودع. راجع أي تعديلات خاصة أجريتها في قاعدة البيانات. سياسات Storage الموجودة مسبقًا لا تُحذف؛ تأكد من عدم وجود سياسة عامة أخرى تسمح للزوار برفع ملفات في الحاوية الجديدة.

## ما تغيّر في الحفظ والصور

- يُعرض نجاح الحفظ بعد تأكيد الخادم فقط. يحتاج التعديل اتصالًا بالإنترنت؛ عند انقطاعه تبقى آخر نسخة محفوظة للقراءة.
- التعديلات المتزامنة تُفحص باستخدام `updated_at`. عند التعارض، حدّث القائمة وأعد فتح النموذج؛ لا يُكتب فوق إصدار جهاز آخر تلقائيًا.
- حذف تصنيف وأصنافه عملية واحدة عبر علاقة `ON DELETE CASCADE`.
- لا تُعاد مزامنة الطابور القديم تلقائيًا. مفاتيح `crepe_cart_*_v1` القديمة تُترك كما هي. إن وُجدت تعديلات قديمة معلّقة، احتفظ بنسخة خاصة من بيانات المتصفح قبل مسحها وأعد إدخال المطلوب يدويًا بحساب المدير بعد مقارنة القائمة. قد تحتوي الإعدادات القديمة على PIN، فلا تنشر النسخة الاحتياطية.
- الصور الجديدة تُضغط ثم تُرفع إلى حاوية `crepe-menu-images`. صور هذه الحاوية **عامة للزبائن**؛ لا ترفع مستندات أو صورًا خاصة. الحد 2 ميغابايت بعد الضغط. الصور القديمة المخزنة بصيغة Base64 لا تُحذف أو تُنقل تلقائيًا. إلغاء النموذج بعد الرفع قد يترك صورة غير مستخدمة يمكن حذفها من Storage لاحقًا.
- تغيير العملة الأساسية مع وجود أصناف محظور حتى لا تتغيّر دلالة الأسعار دون تحويلها. يمكنك تعديل سعر الصرف. التحويل الكامل لأسعار قائمة قائمة يتطلب إجراءً مستقلًا.
- القيود الجديدة لا تعيد كتابة الأسعار القديمة غير الصالحة؛ راجعها وصححها قبل تعديل صفوفها.

## التحقق

```sh
npm ci
npm run check
npm audit
```

تشمل الاختبارات رفض الكتابة لغير المدير، فشل الحفظ، تعارض الإصدارات، سباق القراءة والحفظ، الحذف المتسلسل، التخزين المحلي، الروابط والتحقق من القيم. تُنفذ سياسة SQL نفسها في PostgreSQL محلي عبر PGlite مع أدوار Auth وStorage تجريبية؛ ذلك لا يُثبت حالة صلاحيات مشروع الإنتاج. البناء يتحقق من TypeScript بوضع strict. اختبار واجهة تفاعلي شامل وتجربة APK على هاتف فعلي لم يُنفّذا محليًا.

## Android

مسار GitHub Actions يُنتج **Debug APK**. اضبط GitHub Actions secrets:
`VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`، ومتغير Actions `VITE_PUBLIC_MENU_URL`.
تُستخدم Node.js 22 وJava 21 و`npm ci` مع ملف قفل npm. مجلد Android يُولّد أثناء البناء؛ لا توجد تعديلات أصلية مخصصة محفوظة فيه. إصدار متجر التطبيقات يحتاج إعداد توقيع وإصدار Release مستقلًا.
